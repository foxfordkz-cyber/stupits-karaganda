# Ядро и CLI — Дамир

Работающий модуль чтения, пяти технических проверок и экспорта по человеческим решениям. Код и тесты находятся только в `modules/core/`; общие схемы, зависимости и чужие модули не изменены. Node.js >=22, зависимости устанавливаются существующей командой `npm ci` из корня репозитория.

## Запуск

Из корня репозитория, без установки глобального пакета:

```powershell
.\modules\core\locqa.cmd check --source fixtures/synthetic/source.arb --target fixtures/synthetic/target.arb --glossary fixtures/synthetic/glossary.csv --out outputs/core-demo
```

Чтобы использовать точную команду из брифа в текущем PowerShell:

```powershell
$env:Path = (Resolve-Path .\modules\core).Path + [IO.Path]::PathSeparator + $env:Path
locqa check --source fixtures/synthetic/source.arb --target fixtures/synthetic/target.arb --glossary fixtures/synthetic/glossary.csv --out outputs/core-demo-2
```

На Linux/macOS: `modules/core/locqa check ...`. Универсальный вариант: `node modules/core/cli.mjs check ...`. Если `@@locale` отсутствует, добавьте `--source-locale ru --target-locale kk`. Явная локаль не может противоречить существующей метке.

`--out` — **новый каталог**. Каждый запуск требует отдельного имени: существующие каталоги и входные файлы не перезаписываются. Внутри репозитория разрешены только подкаталоги игнорируемых `outputs/`, `private/`, `data/`, `submission/`; проверяются также ссылки на каталоги. Проверка чтения UTF-8 строгая, без замены повреждённых байтов.

Коды завершения: `0` — чистая проверка/успешный экспорт; `1` — найдены конкурсные проблемы; `2` — структурные проблемы, ошибка входных данных или заблокированный экспорт. Синтетический сломанный пример ожидаемо возвращает `1`.

## Результаты проверки

| Файл | Содержание |
|---|---|
| `bundle.json` | Общий контракт v1, точные SHA-256 текстов, вхождения, разделы и описания |
| `report.json` | Только девять согласованных полей; пять типов ядра; все `reviewed_by_human=false` |
| `trace.json` | Индекс находки в report и связанные `entry_id`; одинаковые находки объединены без потери вхождений |
| `diagnostics.json` | Дубли, структура/имена ключей, некорректный исходный ICU, технические символы, лишние целевые ключи |
| `audit.json` | Хэши файлов, все свойства в порядке входа, сырые фрагменты, позиции UTF-16 и номера строк/колонок с 1 |
| `manifest.json` | Режим `live_core_detection`, версии Node/ICU, параметры длины, числа находок и структурных ошибок |
| `failure.json` | Причина аварийного завершения после резервирования выходного каталога |

Эти файлы содержат производные данные и должны оставаться вне Git. `audit.json` сохраняет в том числе все повторные `@@comment` и метаданные; целевые ключи без источника не попадают в парный bundle. При конфликтующих исходных дублях записи этого ключа исключаются из bundle до согласованного выбора исходного значения. Обычные целевые дубли сохраняют отдельные `entry_id`.

Правила:

- `untranslated`: отсутствующий, пустой или состоящий из пробелов перевод непустого источника; отсутствие отличается от пустой строки.
- `same_as_source`: точное совпадение текста. Числа, символы и сообщения только из ICU-переменных исключены. Допустимые неизменные слова/бренды берутся из одинаковых RU/KK значений CSV, с сопоставлением регистра. Имена и другие бренды без записи в глоссарии могут дать ложные срабатывания.
- `placeholder_mismatch`: имена и типы ICU-аргументов, select-ветви, форматирование чисел/дат, printf-параметры и теги. Проверяется также вложенность и техническое содержимое отдельных ветвей.
- `plural_mismatch`: синтаксис, обязательная `other`, вид cardinal/ordinal, offset, точные `=N`-ветви и вложенная структура. Категории берутся из CLDR через `Intl.PluralRules` целевой локали. RU `few/many` не требуются в KK. Отсутствующие необязательные категории используют `other`; неиспользуемые в данной локали категории отмечаются отдельно в объяснении.
- `length_overflow`: число видимых графем >2× источника, источник не длиннее 20 графем, цель не короче 10. Настройки: `--length-ratio`, `--short-limit`, `--length-minimum`. В ICU берётся самая длинная ветвь, ширина подстановок неизвестна.

Глоссарий: CSV с колонками локалей (например `ru,kk,en,comment`), поддерживаются кавычки, запятые и переносы внутри полей. Ядро использует только исключения совпадающих терминов; проверка `glossary_violation` принадлежит языковому модулю. CSV только с заголовком допустим, но исключений у него нет. Автоматические исправления не предлагаются: `suggestion` остаётся пустым.

## Экспорт

```powershell
.\modules\core\locqa.cmd export --source data/intl_ru.arb --target data/intl_kk.arb --reviews private/reviews.json --source-locale ru --target-locale kk --out submission/core-approved
```

Результат — `intl_kk_fixed.arb` (имя зависит от целевой локали) и `export-audit.json`. Экспорт:

- Валидирует общий контракт reviews, локаль, `entry_id`, исходный текст и все три хэша. Изменение источника, первоначального перевода или одобренной версии блокирует устаревшее решение. Флаг в report не используется как разрешение на исправление.
- Применяет только `accepted`/`edited`, сохраняет неизменённые значения, повторные разделители и существующие метаданные. Для добавляемого перевода копирует доступные исходные метаданные без прежней отметки проверки.
- Переносит шесть полей `@key.x-locqa` из предоставленного решения. Неподтверждаемые прежние `true`-метки удаляются с записью в аудит; ложные/тестовые метки не повышаются до `true`. Производственного метода создания одобрения нет.
- Проверяет ICU, printf, теги, переносы/табы, private-use и format-символы, символы категории Unicode `S`, вариационные селекторы, сущности, обратные слеши, экранированные фигурные скобки, `%%` и удвоенные ICU-апострофы. Нельзя удалить дополнительный защищённый символ исходного target даже при исправлении повреждённого ICU.
- Блокирует **любые** обычные дубли, включая одинаковые, и дубли атрибутов. Нормализация требует отдельного согласованного решения интегратора; последний дубль не выбирается молча.
- Повторно выполняет независимый `checkRelease` интегратора перед записью. Все проверки проходят до создания итогового ARB. Пустой журнал не меняет переводы.

API для интегратора экспортируется из `modules/core/index.mjs`: `readArb(text, side)`, `checkArbs({sourceText, targetText, glossaryText?, sourceLocale?, targetLocale?, lengthRatio?, shortLimit?, lengthMinimum?})`, `exportApproved({sourceText, targetText, reviews, sourceLocale?, targetLocale?})`. `checkArbs` возвращает объекты перечисленных файлов, `exportApproved` — `{text, audit}` без записи на диск. За приватное место хранения при прямом использовании API отвечает вызывающий код.

## Проверки и ограничения

```powershell
npm test
npm run check
node modules/core/scripts/flutter-smoke.mjs
```

Последняя команда — отдельный интеграционный тест с настоящим Flutter SDK. Она экспортирует вымышленное изменение с явно названным `TEST_DOUBLE_NOT_A_HUMAN_REVIEW`, проверяет `x-locqa` и вложенный ICU через `flutter gen-l10n`, затем ожидает отказ генератора на искусственном недопустимом имени ключа. Тестовые одобрения не являются человеческой проверкой; реальные файлы скрипт не читает. Логи и результаты сохраняются только в новом `outputs/core-flutter-test-*`.

Проверено 30.10.2026: Node 24.17.0, Flutter 3.41.2 / Dart 3.11.0. Модульные тесты входят в общий `npm test`. Успех на синтетике не доказывает полноту или качество на скрытом наборе.

Для выпуска требуется дополнительный прогон **точной итоговой пары**:

```powershell
npm run flutter-smoke -- --source data/intl_ru.arb --target submission/core-approved/intl_kk_fixed.arb --source-locale ru --target-locale kk --out outputs/flutter-final
```

`flutter_verified` у самого ядра всегда `false`: только отдельный реальный прогон даёт доказательство. ICU-парсер поддерживает больше конструкций, чем Flutter; smoke-test остаётся обязательным. Ширина виджетов, качество казахского текста и личность проверяющего не устанавливаются. `confidence` не калибрована как вероятность. Сохранение технических символов консервативно: изменение их количества между plural-ветвями или конфликтный baseline может потребовать ручного согласования. Отсутствующие переводы без одобрения остаются отсутствующими и отмечаются независимой проверкой; генерация с fallback не доказывает полноту локализации.

Ориентиры: [Flutter internationalization](https://docs.flutter.dev/ui/internationalization), [Unicode CLDR plural rules](https://cldr.unicode.org/index/cldr-spec/plural-rules). Общие контракты: [CONTRACTS.md](../../docs/CONTRACTS.md).
