# Передача модуля отчёта и интерфейса

Область: `modules/report/`, ветка `tony/report-review-ui`. Модуль принимает согласованные report/bundle, создаёт самостоятельный HTML и сохраняет рабочие решения отдельно от человеческих проверок. Общие схемы, зависимости, чужие модули и исходные данные не изменяются.

Матрица связывает требования задания с реализацией и фактически выполненными проверками. Автоматический тест модели и просмотр исходного кода сами по себе не подтверждают браузерное взаимодействие.

## Требования задания

| Требование | Реализация | Проверка и её границы |
|---|---|---|
| Карточка «оригинал → текущий перевод → проблема → предложение» | Четыре блока, тип, серьёзность, evidence, confidence и контекст bundle | `model.test.mjs`: привязка всех 11 согласованных находок; браузерный проход по всему пакету |
| Фильтры по типу, серьёзности и статусу | 11 типов, три уровня, рабочие/импортированные статусы, поиск и сброс | Реализованы в `template.html` / `client.mjs`; браузер подтвердил статусный фильтр с очередью от 11 до 0; автоматический тест проверяет навигацию после исчезновения обработанной карточки |
| «Принять», «исправить», «отклонить» | accepted / edited / rejected, автор, комментарий, точная версия текста; можно убрать черновик | Автотесты трёх решений и неизменности исходников; браузер сохранил и восстановил все три статуса |
| Сохранение и повторный импорт решений | JSON workspace и HTML-снимок; проверка до изменения состояния | JSON/HTML roundtrip в автотестах; браузерное повторное открытие сохранило 11 решений, начальные пробелы и перенос строки |
| Самостоятельный HTML, открывающийся локально | Данные, стили и runtime встроены; внешние script/styles не нужны | `render.test.mjs`: автономная структура, безопасное встраивание и компиляция runtime; HTML повторно открыт через localhost. Прямой `file://` отклонён политикой инструмента и не считается проверенным |
| Сводка подтверждённых проблем | Импорт существующей анкеты `human_precision_sample`; подтверждённые, неподтверждённые и непроверенные находки считаются отдельно | `precision.test.mjs`: точное совпадение с общим `scorePrecisionReview`; браузер загрузил незаполненную синтетическую анкету на 11 находок и показал 0 подтверждений |
| Сводка проверенных исправлений | Отдельный счётчик и список применимых accepted / edited из reviews, меняющих исходный перевод | Автотесты применимости и сохранности импортированных reviews; одобрение строки не используется как подтверждение каждого issue_type |
| Старт на `report.sample.json` со всеми 11 типами | Demo использует согласованный report и полный bundle из существующего синтетического адаптера | Автотесты: 11 карточек, 11 типов и точная привязка. Demo обозначено как воспроизведение подготовленных находок |
| Обработать пакет, сохранить, открыть и передать эксперту без потери статусов | Навигация, следующая без решения, рабочий журнал, конфликты, экспертный режим со всеми находками | Автотесты истории, конфликтов и фильтрованной навигации; браузер обработал все 11 карточек и повторно открыл экспертный HTML с 11 карточками и 11 строками сводки типов |
| Предпросмотр длинной строки в кнопке и вкладке | Текущий и рабочий текст, регулируемая ширина, сообщение о риске переполнения | Реализовано в `client.mjs`. Реальные размеры и шрифт игры неизвестны; макет не доказывает дефект в клиенте |
| Не изменять исходники и не выставлять отметку человека | UI создаёт только черновики; CLI защищает входы; человеческие записи только импортируются | Тесты неизменности входов, hard/symbolic links и отсутствия `reviewed_by_human` у черновиков. Реальные анкеты и одобрения не создавались |

## Запуск и передаваемые форматы

Демонстрация на искусственных данных, с новым выходным каталогом:

```sh
npm ci
node modules/report/demo.mjs --out outputs/tony-demo-handoff
```

Результат с этим явным `--out`: `outputs/tony-demo-handoff/report.html`; каталог должен быть новым. Без `--out` каждый запуск автоматически создаёт отдельный `outputs/tony-demo-<суффикс>`. Точный путь к HTML печатается в stdout.

Подключение к выходам соседних модулей и существующим человеческим записям:

```sh
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --out outputs/report.html
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --reviews private/reviews.json --precision-sample private/precision-sample.json --out outputs/expert.html
```

Вторая команда читает уже существующие локальные файлы; она не создаёт и не заполняет человеческие ответы. Подробности импорта и сочетания аргументов: [README.md](README.md).

| Формат | Что передаётся |
|---|---|
| HTML | Самостоятельное рабочее место и полный экспертный отчёт, встроенные входы, сохранённые решения и режим просмотра |
| Workspace v1 | Текущие и устаревшие черновики, импортированный reviews; прежний формат продолжает читаться |
| Workspace v2 | Те же поля плюс исходный объект `imported_precision`; используется при наличии анкеты |
| Экспорт reviews | Только применимые записи уже импортированного человеческого журнала, без преобразования черновиков |

Устаревшая либо некорректная прикреплённая анкета в workspace v2 сохраняется с причиной и не учитывается в сводке. Применимые черновики и reviews при этом восстанавливаются; повторный экспорт сохраняет анкету для разбора. Нарушенная структура workspace и ошибочный прямой импорт отдельной анкеты отклоняются.

## Подтверждённый браузерный маршрут

Владелец модуля выполнил через localhost следующий маршрут на синтетических данных:

1. Обработал все 11 карточек при активном фильтре «Без рабочего решения»: принято одно предложение, сохранена одна правка, отклонено одно предложение, затем приняты ещё восемь. Счётчик оставшейся очереди последовательно уменьшился с 10 до 0.
2. Импортировал незаполненную каноническую анкету precision на все 11 находок. Интерфейс показал 0 подтверждений; человеческие ответы не создавались.
3. Открыл экспертный режим: отображены 11 карточек и 11 строк сводки по типам.
4. Сохранил JSON workspace v2 и экспертный HTML, затем повторно открыл HTML через localhost. Сохранились 11 черновиков, все три статуса, анкета precision и экспертный режим.
5. Проверил сохранение начальных пробелов и переноса строки. После повторного открытия фильтр типов содержал 12 вариантов: «Все типы» и 11 типов, без дублирования.
6. Убрал отклонённое рабочее решение: счётчик изменился с 11 на 10, карточка вернулась через «К следующей без решения» с правильным ключом. Исходные строки и анкета сохранились.
7. Проверил узкий экран: ширина содержимого совпала с шириной документа, горизонтального переполнения страницы не было. На широком экране показаны очередь и карточка рядом. Предпросмотр длинной строки вывел предупреждение о переполнении условного макета.
8. Импортировал файл с JSON `null` в восстановленную сессию: получено понятное сообщение об отказе, все 11 рабочих решений остались на месте.

Прямой переход к `file://` фактически отклонён политикой инструмента браузерной автоматизации. Успех прямого открытия с диска не заявляется. Такой запуск остаётся отдельной ручной проверкой в поддерживаемом браузере.

Браузерные сценарии конфликта нескольких рабочих версий и печати отдельно не выполнялись. Конфликты покрыты тестами модели; перед печатью `beforeprint` формирует полный экспертный отчёт.

## Известные ограничения

- Интерфейс не создаёт человеческие одобрения. Заполненные reviews и анкета precision должны поступить от назначенного человека через процесс команды.
- Подтверждённая проблема и проверенное исправление — разные показатели из разных источников. Частичная анкета описывает только проверенную часть; legacy-анкета без хэша всего отчёта не даёт оценки, привязанной ко всей его версии.
- Хэши не удостоверяют личность проверяющего и не выявляют замену seed при совпавшем составе выборки.
- До скачивания JSON или HTML изменения находятся в памяти браузера. Автосохранения на диск и localStorage нет.
- Нужен современный браузер с JavaScript и Web Crypto; прямой `file://` требует ручного подтверждения.
- Неоднозначные ключи блокируют решения. Разрешение дублей, согласование конфликтующих переводов, экспорт ARB, Flutter и языковая проверка остаются у соответствующих участников команды.
- Предпросмотр длины использует условные размеры и шрифт и показывает риск, а не доказанный дефект игры.
