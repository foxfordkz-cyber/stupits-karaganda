# Отчёт и интерфейс — Тони

Автономный HTML для проверки локализации: оригинал → текущий перевод → объяснение → предложение. Все исходники и тесты находятся в `modules/report/`. Общие контракты, зависимости, исходные ARB и чужие модули не меняются.

## Запуск

Node.js 22+; команды из корня репозитория. Используются уже объявленные зависимости:

```sh
npm ci
node modules/report/demo.mjs
```

Откройте `outputs/tony-demo/report.html` в современном браузере. HTML включает стили, код и данные; сервер и сеть для работы не нужны. Для повторной генерации укажите **новый** каталог: `node modules/report/demo.mjs --out outputs/tony-demo-002`. Demo не перезаписывает существующий каталог.

Demo использует существующий `fixtures/synthetic/adapters/adapter.mjs normalize`, чтобы получить полный bundle из согласованных искусственных ARB. Затем воспроизводит все 11 типов из `report.sample.json`. Это не запуск детектора и не измерение его качества. `contracts/examples/bundle.json` содержит только три записи и недостаточен для всех карточек.

## Подключение к pipeline

Интерфейс совпадает с существующей стадией render в `contracts/examples/pipeline.json`:

```sh
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --out outputs/report.html
```

Входы проверяются общими `assertContract`. CLI отклоняет запись поверх любого входа, в том числе через hard link или symlink. Родительский каталог результата создаётся автоматически. Существующий выходной HTML, если он не совпадает с входом, можно пересобрать.

Дополнительно разрешён **один** из параметров:

```sh
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --workspace private/review-workspace.json --out outputs/restored.html
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --reviews private/reviews.json --out outputs/reviewed.html
```

`--workspace` и `--reviews` вместе запрещены, чтобы один журнал не заменял другой неявно. `--synthetic` включает заметную пометку искусственных данных. Генератор не исправляет ARB и не изменяет report/bundle.

## Работа редактора и передача

1. Выберите карточку. Фильтры доступны по 11 типам, серьёзности и статусу; поиск — по ключу, оригиналу, переводу, предложению и объяснению.
2. «Принять» сохраняет точное предложение. «Сохранить правку» сохраняет вашу версию, включая намеренную пустую строку. «Отклонить» записывает отказ. Изменение текста автоматически обновляет рабочую сессию; имя автора и комментарий сохраняются с решением.
3. «Сохранить решения» скачивает `review-workspace.json`. «Импорт решений» восстанавливает его целиком после проверки. Если сессия непустая, интерфейс предупреждает о замене; сначала сохраните нужный файл. Ошибочный импорт оставляет текущие решения нетронутыми.
4. «Сохранить HTML» скачивает самостоятельный снимок вместе с решениями и историей устаревших записей. При повторном открытии состояния восстанавливаются. Он подходит для передачи эксперту без отдельного JSON.
5. «Экспорт reviews» содержит **только уже импортированные применимые** решения официального журнала. При отсутствии журнала это валидный пустой `decisions: []`.

**Кнопки создают только рабочие решения и никогда не выставляют `reviewed_by_human`.** По ограничению задачи модуль не превращает черновики в человеческие одобрения. Завершённый официальный `reviews` должен поступить от реального проверяющего через согласованный процесс команды. Импортированный журнал сохраняется без изменения записей и не доказывает личность или факт проверки сам по себе.

Сводка различает кандидатов, рабочие решения, строки с применимыми проверками и принятые исправления. Проверка одной строки не подтверждает автоматически каждый тип находки на этой строке: reviews не содержит решения по конкретному issue_type. Несколько черновиков разных находок одной строки могут предлагать разные варианты; итоговый выбор одного перевода остаётся человеку.

## Рабочий формат и восстановление

Формат локальный для модуля, не заменяет общие схемы:

```json
{
  "kind": "qazaq-loc-qa-workspace",
  "version": 1,
  "target_locale": "kk",
  "drafts": [],
  "imported_reviews": { "schema_version": "1.0", "target_locale": "kk", "decisions": [] }
}
```

Черновик содержит `card_id`, `key`, `entry_id`, `source_hash`, `original_hash`, `suggestion_hash`, `decision`, `proposed_text`, `proposed_hash`, `note`, `updated_at`, `author`. Решения: `accepted`, `edited`, `rejected`. У отказа `proposed_text` и `proposed_hash` равны `null`. Хэши SHA-256 вычисляются по точному UTF-8 без обрезки пробелов или нормализации Unicode. Для отсутствующего target хэш `null`; для пустой строки вычисляется обычный хэш.

Идентификатор карточки привязан к полному снимку находки. Изменённые исходник, перевод, предложение или контекст находки делают старое рабочее решение неприменимым. Такие записи остаются в рабочем файле и журнале с причиной. Устаревшая история и одно новое применимое решение той же карточки могут сосуществовать; два применимых решения одной карточки отклоняются. Неоднозначные ключи bundle и несовпадение текста report/bundle блокируют действия.

Официальный reviews проверяется по локали, полям, датам, уникальности entry_id, точным исходным и одобренным текстам/хэшам. Повреждённый файл отклоняется целиком; корректный, но устаревший журнал сохраняется в рабочем файле, а неприменимые записи исключаются из экспорта reviews. Изменение одобренного текста без согласованного хэша отклоняется. Чужая локаль отклоняется целиком.

## Проверки и ограничения

```sh
node --test modules/report/test/*.test.mjs
npm test
npm run check
```

Тесты охватывают все типы, три решения и повторный импорт, null/пустую строку, Unicode/пробелы, устаревшие решения, дубли, неверную локаль, повреждённые хэши, поддельные поля черновика, сохранность входов, hard/symbolic links, встраивание `</script>` и сборку автономного runtime. Синтетические mock reviews с отметкой человека используются только внутри тестов валидатора и не попадают в демонстрационный отчёт.

Браузерная проверка: принятие, правка, отклонение, фильтры, загрузка JSON/HTML и восстановление трёх статусов; узкий и широкий экран. Прямой переход `file://` запрещён политикой инструмента автоматизации, поэтому повторное открытие проверено через localhost. Прямое открытие с диска требует современного браузера с Web Crypto и должно быть дополнительно подтверждено вручную.

Предпросмотр кнопки и вкладки иллюстрирует риск длины на выбранной ширине. Реальных размеров и шрифта игры нет; макет не доказывает дефект. Проверка в игровом клиенте, языковая оценка носителем, разрешение дублей и экспорт ARB остаются отдельными этапами команды.

Нет сервера, localStorage и скрытого автосохранения на диск. До закрытия страницы нужно скачать JSON или HTML; браузер предупреждает о несохранённых изменениях. Входные строки отображаются через textContent; JSON экранирован, CSP запрещает сетевые запросы. Реальные данные и результаты храните в игнорируемых `private/` или `outputs/`.
