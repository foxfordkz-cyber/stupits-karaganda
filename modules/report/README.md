# Отчёт и интерфейс — Тони

Автономный HTML для проверки локализации: оригинал → текущий перевод → проблема → предложение. Карточки предназначены для редактора; режим «Отчёт для эксперта» показывает весь пакет находок и решений. Все исходники и тесты находятся в `modules/report/`. Общие контракты, зависимости, исходные ARB и чужие модули не меняются.

**Модуль не выставляет отметки проверки человеком.** Кнопки создают рабочие решения. Подтверждённые проблемы и проверенные исправления появляются только из отдельно импортированных существующих человеческих записей. Реальные анкеты и одобрения при разработке не создаются.

Матрица требований и фактические результаты проверок: [ACCEPTANCE.md](ACCEPTANCE.md).

## Запуск

Node.js 22+; команды из корня репозитория. Используются уже объявленные зависимости:

```sh
npm ci
node modules/report/demo.mjs
```

Без `--out` каждый запуск создаёт новый каталог `outputs/tony-demo-<суффикс>`. Команда печатает точный путь к `report.html`; откройте его в современном браузере с JavaScript и Web Crypto. HTML включает стили, код и данные; сервер и сеть для работы не нужны. Чтобы выбрать выходной каталог явно:

```sh
node modules/report/demo.mjs --out outputs/tony-demo-002
```

Явный `--out` должен указывать новый каталог: существующий не перезаписывается. Demo получает полный bundle через существующий синтетический адаптер `fixtures/synthetic/adapters/adapter.mjs normalize`, затем воспроизводит все 11 типов из `report.sample.json`. Это не запуск детектора и не измерение качества. `contracts/examples/bundle.json` содержит только три записи и недостаточен для всех карточек.

## Подключение к pipeline

Интерфейс совпадает со стадией render в `contracts/examples/pipeline.json`:

```sh
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --out outputs/report.html
```

Восстановление сессии или подключение уже существующих человеческих записей:

```sh
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --workspace private/review-workspace.json --out outputs/restored.html
node modules/report/render.mjs --bundle outputs/bundle.json --report outputs/report.json --reviews private/reviews.json --precision-sample private/precision-sample.json --out outputs/expert.html
```

`--reviews` и `--precision-sample` необязательны и могут использоваться отдельно. Анкета `human_precision_sample` создаётся общим инструментом `sample-review` и заполняется человеком по [процессу команды](../../docs/HUMAN_EVALUATION.md); этот модуль только читает её. Незаполненная и частично заполненная анкеты допустимы.

`--workspace` вместе с `--reviews` запрещены, чтобы один журнал не заменял другой неявно. Workspace с уже прикреплённой анкетой нельзя дополнить `--precision-sample`: замените анкету явно через интерфейс. `--synthetic` включает заметную пометку искусственных данных.

Входы проверяются общими контрактами. CLI отклоняет запись поверх любого входа, в том числе через hard link или symlink. Родительский каталог результата создаётся автоматически. Существующий выходной HTML, не совпадающий с входом, можно пересобрать. Исходные report/bundle и ARB не изменяются.

## Работа редактора и передача

1. Выберите карточку. Есть поиск, фильтры по 11 типам, серьёзности и статусу, «Сбросить фильтры» и «К следующей без решения». Последняя кнопка снимает фильтры, чтобы показать найденную карточку.
2. «Принять» сохраняет точное предложение. «Сохранить правку» сохраняет вашу версию, включая намеренную пустую строку. «Отклонить» записывает отказ. Ввод текста автоматически обновляет рабочую сессию; автор и комментарий сохраняются с решением.
3. «Убрать рабочее решение» удаляет текущий черновик карточки. Исходные строки, импортированные проверки и устаревшая история сохраняются. Разные рабочие переводы одной строки отмечаются как конфликт; варианты остаются в журнале для явного согласования.
4. «Сохранить решения» скачивает `review-workspace.json`. «Сохранить HTML» скачивает самостоятельный снимок с решениями, историей и режимом просмотра. При повторном открытии статусы восстанавливаются.
5. «Отчёт для эксперта» показывает сводку по типам, проверенные исправления и **все находки**, независимо от фильтров очереди. Его можно сохранить в HTML для передачи; предусмотрено представление для печати.

«Импорт решений» распознаёт три формата:

| Файл | Что восстанавливается или заменяется |
|---|---|
| Workspace | Сессия целиком, включая черновики, историю, reviews и прикреплённую анкету |
| Официальный reviews | Только журнал решений по строкам; черновики сохраняются |
| Анкета `human_precision_sample` | Только анкета проверки находок; черновики и reviews сохраняются |

Проверка выполняется до изменения сессии. Перед заменой непустых данных интерфейс предлагает подтверждение. Ошибочный прямой импорт оставляет сессию нетронутой.

«Экспорт reviews» содержит **только уже импортированные применимые** решения официального журнала. Без него экспортируется валидный `decisions: []`. Устаревшие записи остаются в workspace. Черновики и анкета precision не преобразуются в человеческие одобрения перевода.

Сессия остаётся в памяти до скачивания JSON или HTML. Нет скрытого автосохранения на диск или localStorage. Браузер предупреждает о несохранённых изменениях; неудавшееся сохранение рабочей правки блокирует экспорт до устранения ошибки.

## Что означает сводка

| Показатель | Основание |
|---|---|
| Кандидаты | Находки report; это ещё не подтверждённые ошибки |
| Рабочие решения | Текущие accepted / edited / rejected без отметки человека |
| Подтверждённые проблемы | Существующие `reviewed: true` и `correct: true` в применимой анкете precision |
| Строки с проверкой | Применимые записи reviews, включая отклонения |
| Проверенные исправления | Применимые accepted / edited из reviews, изменяющие исходный перевод |

Одобрение строки в reviews не подтверждает каждый issue_type на ней. Для этого нужна анкета precision. Без анкеты число подтверждённых проблем показано как «—», а не как нулевое число ошибок.

Проверка анкеты совпадает с общим `scorePrecisionReview`: точная версия report, состав и идентификаторы выборки, размер, seed, хэши и полнота ответов. Частичная выборка описывает только просмотренную часть. Legacy-анкета без `report_sha256` привязана лишь к выбранным находкам. Хэши не доказывают личность проверяющего; формат также не обнаруживает замену seed, если состав выбранных строк остался тем же.

## Рабочий формат и восстановление

Формат локальный для модуля, общие схемы не меняет. Без анкеты экспортируется прежняя версия 1:

```json
{
  "kind": "qazaq-loc-qa-workspace",
  "version": 1,
  "target_locale": "kk",
  "drafts": [],
  "imported_reviews": { "schema_version": "1.0", "target_locale": "kk", "decisions": [] }
}
```

При наличии анкеты экспортируется версия 2 с дополнительным `imported_precision`, содержащим её исходный объект. Версия 1 продолжает читаться. Поля черновика: `card_id`, `key`, `entry_id`, `source_hash`, `original_hash`, `suggestion_hash`, `decision`, `proposed_text`, `proposed_hash`, `note`, `updated_at`, `author`. У отказа текст и хэш предложения равны `null`.

SHA-256 вычисляется по точному UTF-8 без trim или нормализации Unicode. Отсутствующий target имеет хэш `null`; пустая строка имеет обычный хэш. Идентификатор карточки привязан к полному снимку находки. Изменение исходника, перевода, предложения или данных находки делает старый черновик неприменимым; он сохраняется с причиной. Устаревшая история и одно новое применимое решение могут сосуществовать. Неоднозначный bundle или несовпадение текстов блокируют действия.

Reviews проверяется по локали, полям, датам, уникальности entry_id и точным текстам/хэшам. Повреждённый журнал отклоняется целиком; корректные устаревшие записи сохраняются отдельно и не считаются применимыми.

Устаревшая или некорректная прикреплённая анкета в workspace v2 сохраняется с причиной и не учитывается в сводке. Применимые черновики и reviews восстанавливаются, повторный экспорт сохраняет анкету для разбора. Нарушенная структура самого workspace — например, отсутствие `imported_precision` в версии 2 — отклоняет импорт. Отдельно переданная устаревшая анкета отклоняется целиком.

## Проверки и ограничения

```sh
node --test modules/report/test/*.test.mjs
npm test
npm run check
```

Автотесты охватывают восстановление решений, точные хэши, историю, конфликты, навигацию, precision, версии workspace, защиту входов, экранирование HTML и синтаксис автономного runtime. Mock reviews и ответы precision существуют только в синтетических тестовых объектах; демонстрационный отчёт не содержит созданных агентом одобрений.

Браузерный маршрут через localhost подтвердил обработку всех 11 карточек, три статуса, точные пробелы/переносы, сохранение JSON v2 и экспертного HTML, повторное открытие с анкетой и всеми находками. Прямой переход `file://` отклонён политикой инструмента автоматизации; открытие с диска требует отдельной ручной проверки. Подробности и окончательные результаты: [ACCEPTANCE.md](ACCEPTANCE.md).

Предпросмотр кнопки и вкладки иллюстрирует риск длины при выбранной ширине. Реальных размеров и шрифта игры нет; макет не доказывает дефект. Языковая оценка носителем, разрешение дублей, окончательный выбор среди конфликтующих черновиков, экспорт ARB и проверка игрового контекста остаются отдельными этапами команды.

Входные строки отображаются через textContent; JSON экранирован, CSP запрещает сетевые запросы. Реальные данные и результаты храните в игнорируемых `private/` или `outputs/`.
