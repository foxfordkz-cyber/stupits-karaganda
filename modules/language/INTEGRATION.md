# Передача языкового модуля интегратору

Версия 1.3.1. Требуются Python 3.10+ и штатные Node-зависимости репозитория. Собственных внешних Python-зависимостей нет. Общая схема v1 остаётся источником истины; ниже описано подключение существующего контракта.

## Команда стадии

Из корня репозитория:

```text
node modules/language/check.mjs --bundle contracts/examples/bundle.json --glossary fixtures/synthetic/glossary.csv --out C:/Temp/locqa-private/language-001/report.json
```

`--out` и его `.details` должны быть новыми, вне любого Git checkout. Для Unix используйте аналогичный абсолютный приватный путь. Python выбирается через `--python` или `LOCQA_PYTHON`. Для пилота добавьте `--limit 100`; полный проход — без limit, с прежним `--cache`.

## Вход и выход

| Сторона | Контракт |
|---|---|
| Ядро → language | bundle v1: key, entry_id, occurrence, source/target, SHA-256 точного UTF-8, context; RU → KK |
| Лингвист → language | CSV ru,kk,en,comment либо расширенный JSON глоссария; CSV импортируется как draft |
| language → merge/UI | Массив находок с ровно девятью общими полями, шесть языковых issue_type, reviewed_by_human=false |
| Служебные файлы | finding_index, proposals, diagnostics, metrics, events, skipped_entries внутри `<out>.details` |

Node-адаптер использует общие assertContract для bundle и report. Хэши, entry_id и вхождения проверяются до детектора. Отсутствующий/пустой target и пустой source передаются ядру через skipped_entries; они не превращаются в новые языковые типы.

Индекс finding_index относится **только к отчёту языкового модуля**. После merge нельзя использовать его как индекс объединённого массива: интегратор обязан перенести связь с содержимым находки и entry_id. Неоднозначные дубли нельзя разрешать правилом «последняя строка победила».

Предложения proposals содержат точный исходный/новый хэш и изменяемый диапазон. Это не reviews и не разрешение экспорту. После изменения любого текста/контекста проверяйте применимость заново. Unicode-смещения Python считаются по code points, не UTF-16 индексам JavaScript. Техническую сигнатуру проверяет ядро, реальное одобрение вводит человек.

## Ошибки и выполнение

| Код CLI | Значение | Действие вызывающей стороны |
|---|---|---|
| 0 | Выбранный режим и выбранная часть входа завершены | Проверить mode, selection и metrics перед показом |
| 2 | Частичный результат: карантин, кэш/провайдер/бюджет | Сохранить артефакты как partial; не объявлять модельный проход завершённым |
| 1 | Ошибка настройки, входа или вывода | Пометить задание ошибочным |

Общий pipeline сейчас останавливает последующие стадии при ненулевом коде. Если UI должен показывать partial, это отдельное решение интегратора; модуль не меняет общий runner.

Запускайте процесс в фоновой очереди, не внутри HTTP-запроса. Один writer на SQLite-кэш; не удаляйте lock работающего процесса. Внешний timeout runner должен покрывать всю пачку, внутренний timeout провайдера — один запрос. За остановку дерева процессов отвечает инфраструктура. Наличие находок само по себе не делает код возврата ненулевым.

Для большого cold-прохода на загруженной машине штатных 120 секунд может не хватить. В своей конфигурации pipeline интегратор может задать для language `timeout_ms: 600000` и передать адаптеру `--timeout-ms 600000`; это документированное предложение настройки, общая конфигурация этим PR не изменяется. Если даже этот предел недостаточен, делите корпус на пакеты с учётом ограничения cross-key анализа внутри пакета.

## Модель, confidence и приватность

По умолчанию offline. Для модели нужен доверенный subprocess-адаптер, разрешение на передачу конкретных данных и явный бюджет. Реальный API-адаптер здесь не поставляется; скрытых retries нет. Не добавляйте платные повторы без учёта всех попыток и восстановления после неопределённого usage.

Кэш зависит от записи, контекста, глоссария, правил и конфигурации/промпта модели. Изменение адаптера требует новой revision. Бюджет и прогноз резервации не равны фактическому счёту. При неизвестном usage стоимость null. Confidence — некалиброванная эвристика/уверенность генерации, не вероятность или precision.

Не передавайте приватные выгрузки в CI. Benchmark и smoke используют только созданные для разработки данные; их runtime-выходы тоже направляются вне Git и не публикуются как Actions artifacts этим модулем.

## Минимальный end-to-end smoke

```text
node modules/language/smoke.mjs --out C:/Temp/locqa-private/smoke-001
```

Это общий pipeline `normalize → core → language → merge → render`. Language запускается реально; остальные стадии используют уже существующие командные synthetic fixtures. Проверяются схема, реальные suffix_harmony-находки, false в human-review, отсутствие экспортированного ARB и нулевые внешние запросы. HTML рендерера — тестовая заглушка, а не доказательство работы интерфейса Тони.

Для проверки с настоящим ядром Дамира в отдельном checkout:

```text
node modules/language/smoke.mjs --out C:/Temp/locqa-private/smoke-core-001 --core-root C:/path/to/core-checkout
```

В core-checkout должны быть штатные зависимости и `modules/core/normalize.mjs`, `check.mjs`. Если запрошенных адаптеров нет, тест завершается ошибкой, без молчаливой подмены. Нормализация/ядро/language выполняются реально, renderer остаётся командной заглушкой. На 31.10.2026 такой проход успешно выполнен с ядром `e216ac6`; это совместимость конкретных версий и синтетических входов, не проверка production deployment.

## Действия команды

Интегратор рассматривает Draft PR, подключает модуль и переносит служебные индексы при слиянии. Айдана/носитель проверяет ожидания synthetic benchmark, спорные термины и качество исправлений. Тони подключает отчёт и кандидаты к реальному review UI. Дамир экспортирует только применимые человеческие решения. Отдельно требуются разрешение/бюджет для модели и проверка точного итогового ARB реальным Flutter.

Дополнительно проверен импорт 40 строк CSV Айданы из `d644e43`: общий заголовок принят, статус остался draft, человеческие одобрения не выводились из комментариев. Это проверка совместимости формата, не утверждение лингвистической правильности списка.
