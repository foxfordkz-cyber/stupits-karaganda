# Проверка устойчивости перед интеграцией

Версия 1.3.1: добавлены 77 синтетических случаев с явными ожиданиями, изолированный baseline runner, multi-label метрики, измерения 100/1000/5600 строк и интеграционный smoke. На одном и том же наборе исправление невидимых символов внутри известных слов уменьшило FN с 7 до 5 без роста FP; ограничения разметки и полные значения приведены в benchmark/RESULTS.md. Это не независимая оценка реального казахского текста.

Тесты scorer отдельно проверяют нулевые знаменатели, неверный тип, FP/FN, дубли предсказаний, несколько меток и разные вхождения. Node-тест запускает benchmark CLI и реальный language внутри общего pipeline. Незапрошенное создание человеческих решений и экспорт отсутствуют; недоступное явно запрошенное ядро не подменяется fixture.

Версия 1.3.0 реализует итерацию из [DEVELOPMENT_PROMPT.md](DEVELOPMENT_PROMPT.md). Проверены 108 Python-тестов, 154 Node-теста всего репозитория (10 для командного адаптера) и `npm run check`.

Новые сценарии: иностранное предложение рядом с казахским, несколько иностранных фрагментов без дублирования целой строки, отсутствие срабатывания на одиночный бренд, printf/форматированные ICU-аргументы перед аффиксом, экранированный процент, апострофы, URL и атрибуты. Для новых типов подстановок автоматическая замена текста не создаётся.

Опциональный `glossary_scope=relevant` сохраняет сведения об отборе и хэш полного глоссария. Тесты проверяют исходные/целевые формы, описание, свидетелей, категории, границы слов, неизменность входа и инвалидирование кэша при изменении исключённого термина. Полный контекст остаётся режимом по умолчанию.

Нулевой бюджет проверен с несуществующим executable: адаптер не запускался, фактические запросы и стоимость остались нулевыми, прогноз резервации экспортировался отдельно. Кэшированный модельный результат не учитывается повторно в прогнозе. Все модельные тесты синтетические; платный API не подключался.

Пилот, полный локальный проход и повтор с побайтовой сверкой отчёта, индексов и кандидатов выполнены вне Git. Проверены исходные хэши, общая схема и техническая сигнатура кандидата текущим ядром. Результаты не являются измерением precision/recall. Числа времени и закрытые находки находятся в приватном отчёте передачи.

Локальный набор 1.2.0: 83 Python-проверки, 152 Node-проверки всего репозитория (8 из них для адаптера модуля), `npm run check`. Модельный протокол проверяется синтетическим подпроцессом; это не запуск платной языковой модели. Реальные тексты и подробные метрики запусков остаются в приватном каталоге вне Git. GitHub Actions подтверждает совместимость только для конкретного проверенного коммита.

Локальный анализ и повторы кэша не измеряют языковую точность. Для человеческой проверки используйте `proposals.json` вместе с находками и исходными хэшами; не преобразуйте кандидаты автоматически в `reviews`.

Новые regression tests используют только синтетические данные. Они реально запускают тестовые подпроцессы с timeout, переполнением stdout и большим stderr. Пределы исходного subprocess API проверены по [официальной документации Python](https://docs.python.org/3/library/subprocess.html): буферизация `communicate` не подходит для неограниченного вывода.

Общий запуск тестов:

```text
python -m unittest discover -s tests -v
```

Интегратор должен запускать анализ как фоновое задание. Исключения конфигурации/файловой системы и код `1` превращаются в ошибку задания, а не остановку веб-процесса; код `2` сохраняет частичный отчёт. Одновременные платные задания с одним кэшем следует сериализовать. Отчёт для UI читается после итогового `metrics.json`; для публикации нескольких файлов нужна транзакция/переключение каталога на уровне сервера.

Этот модуль не может подтвердить доступность сайта, состояние базы сайта, секреты deployment, HTTPS, лимиты хостинга, health-check, rollback или нагрузочную устойчивость frontend/backend. Такие проверки выполняются в репозитории интегратора после получения доступа. Исходные выгрузки, частные отчёты и кэш остаются вне Git; схема находки и `reviewed_by_human=false` сохранены.
# Version 1.4 integration

158 Python regressions, including bounded morphology, terminology inflections, polarity,
inline foreign text, transpositions, checkpoint/crash recovery and review-queue identity.
The complete Python suite is now called from the module's Node test, so shared npm CI
executes it without changes to root workflows. Repository Node count: 159.
Original malformed JSON/Unicode, corrupt cache, provider timeout/output bounds, duplicate
occurrence, invalid severity/confidence and source-hash tests remain active.

New failure reasons are whitelisted; no provider exception payload enters logs. An
oversized request cannot reserve charges or launch a provider. A failed final cache
flush marks partial. See PERFORMANCE.md for checkpoint durability and interrupted runs.
Review handoff is a sidecar; existing reviews/history/export contracts remain unchanged.
Real core + report CLI smoke passed on synthetic data; no deployment uptime claim.
