# Воспроизводимый synthetic benchmark

77 вручную составленных AI примеров, 42 ожидаемых метки шести типов. Строки вымышлены; закрытые ARB не использованы. Ожидания заданы в fixtures.py независимо от запуска движка, но **не проверены носителем**. Некоторые примеры создавались со знанием текущих эвристик: это development/regression set, не независимый holdout и не оценка скрытого теста. Пять оставшихся трудных случаев не удалены из знаменателя.

Из modules/language:

```text
python benchmark/run.py --baseline C:/path/to/baseline/modules/language --out C:/Temp/locqa-private/benchmark-001
```

Baseline можно получить через отдельный `git worktree add --detach ... 4d7e001`. Для исторического опубликованного MVP используйте `445079e`. Не меняйте рабочую ветку через reset/rebase. Без --baseline выполняется только текущая версия. Параметр `--sizes ""` отключает масштабный прогон, `--sizes 100,1000,5600` задаёт стандартные размеры.

Каждый движок импортируется отдельным Python-процессом. Одинаковые records/glossary подаются обеим версиям. В evaluation.json сохраняются fingerprint набора, SHA исходников движка, Git SHA и факт незакоммиченных изменений. Это позволяет связать измерение с фактическим кодом, а не только именем ветки.

## Что считается

- Единица оценки: (конкретная входная запись/вхождение, issue_type). Несколько находок одного типа не раздувают TP.
- TP — совпавшие метки; FP — лишние; FN — пропущенные. Micro precision=TP/(TP+FP), recall=TP/(TP+FN), F1=2TP/(2TP+FP+FN).
- При нулевом знаменателе значение null. Пустой набор не означает идеальное качество.
- Per-category и списки FP/FN сохраняются вместе с confusion_cases: ожидаемые/предсказанные типы, missing/unexpected, причина ожидания.
- Это multi-label задача: неверный тип даёт FP и FN. Искусственная однозначная multiclass confusion matrix не строится.
- Кандидаты на аффиксы размечены как ожидаемые **предупреждения о риске**, не как доказанные ошибки каждого возможного имени.

## Производительность и стоимость

100/1000/5600 строк получаются детерминированным повторением примеров с уникальными ключами. Это тест масштаба, не 5600 независимых языковых примеров. Измеряются cold/warm время, число находок/диагностик, cache hit/miss и пик Python-аллокаций через tracemalloc. Прогон проверяет побайтовую одинаковость findings/index/proposals и полный warm cache hit.

Tracemalloc включён во время analyze, поэтому время содержит его накладные расходы. Память не включает загрузку входного JSON, native SQLite или полный RSS процесса. Нельзя сравнивать эти значения с измерениями без tracemalloc или объявлять их полным бюджетом RAM.

Benchmark работает offline: фактические внешние запросы и стоимость равны нулю, LLM cost per 1000 = null, поскольку модель не измерялась. Runtime-артефакты пишутся вне Git. Никакого автоматического upload в Actions нет.

Результаты измерения и оставшиеся ошибки: [RESULTS.md](RESULTS.md). Человеческая оценка correction quality остаётся отдельной задачей команды; высокие synthetic detection-метрики её не заменяют.
