# Бекзат — языковой анализ

Изолированный диагностический модуль для **подготовленных RU→KK записей**. Версия 1.3.1, Python 3.10+, только стандартная библиотека, установка зависимостей Python не требуется. Ветка: `bekzat/stability-hardening`, база: `codex/integration-kit`. Общие зависимости, ядро ARB, UI и файлы других участников модуль не меняет.

Модуль выдаёт кандидаты на шесть языковых типов ошибок. Он не исправляет исходные файлы и всегда возвращает `reviewed_by_human: false`. Решение носителя и проверенная версия текста принадлежат отдельному модулю человеческой проверки.

Подключение команды: [INTEGRATION.md](INTEGRATION.md). Измерения на размеченной синтетике: [benchmark/RESULTS.md](benchmark/RESULTS.md).

Рабочий промпт, границы ответственности и проверяемый план итерации: [DEVELOPMENT_PROMPT.md](DEVELOPMENT_PROMPT.md).

## Подключение к командному pipeline

Из корня репозитория после штатного `npm ci`:

```text
node modules/language/check.mjs --bundle contracts/examples/bundle.json --glossary fixtures/synthetic/glossary.csv --out /absolute/private/run-001/language-report.json
```

На Windows укажите абсолютный приватный путь вне checkout, например `C:/Temp/locqa-private/run-001/language-report.json`. Python 3.10+ должен быть доступен как `python` на Windows или `python3` на остальных системах; иначе передайте `--python` с путём к executable или задайте `LOCQA_PYTHON`. Выходной файл и `<out>.details` должны быть новыми. Пример bundle используется для проверки контракта, а не воспроизведения заранее размеченных находок: адаптер запускает локальный детектор.

`check.mjs` совместим с уже существующим `contracts/examples/pipeline.json` и использует общий `assertContract` для bundle/report. Корневые схемы, зависимости, runner и соседние модули не изменены. Для всего pipeline выбирайте `--out` вне checkout: модуль сохраняет более строгое требование пользователя не держать реальные производные данные внутри репозитория, даже в игнорируемой папке.

`team_cli.py` сохраняет точный командный `source_hash = SHA-256(source)`, `target_hash`, `entry_id`, вхождение и ссылки дополнительных языков. В `<out>.details/finding_index.json` добавлены `entry_id`, `bundle_index`, `target_hash`; официальный report остаётся массивом девяти полей. Записи с отсутствующим/пустым target или пустым source передаются в `skipped_entries.json` как область ядра и не становятся языковыми находками.

Глоссарий принимается как расширенный JSON ниже или командный CSV `ru,kk,en,comment`. CSV импортируется со статусом `draft`: в нём нет машинно проверяемого согласования, запрещённых форм и таблицы склонений. Эти сведения не выдумываются из комментариев. Для поиска терминологических нарушений используйте расширенный JSON. В обоих форматах явно разрешённая форма защищена от локальных эвристик языка/орфографии, только если совпал исходный термин и его раздел; остальной текст проверяется. Это доверие входному глоссарию, а не автоматическое согласование черновика.

По умолчанию выполняется `local_only`. Тот же командный адаптер поддерживает `--limit 100`, `--provider-config`, `--max-requests`, `--max-tokens` и `--max-cost-usd`. Все бюджеты по умолчанию нулевые. Без конфигурации провайдера ненулевой бюджет отклоняется. Пример после настройки адаптера и выделения командой бюджета:

```text
node modules/language/check.mjs --bundle /absolute/private/bundle.json --glossary /absolute/private/glossary.json --out /absolute/private/model-pilot.json --cache /absolute/private/cache --limit 100 --provider-config /absolute/private/provider.json --max-requests 100 --max-tokens 1000000 --max-cost-usd 5 --timeout-ms 600000
```

Числа выше иллюстративные. Пилот выбирает первые N непустых подготовленных записей после проверки всего bundle; пропуски ядра перечислены отдельно. `selected_records`, `available_input_records`, `selection` и `bundle_entries` показывают охват; статус complete относится к выбранной части. Полный проход запускается без `--limit` с тем же кэшем. Межстрочная согласованность оценивается только внутри выбранной части.

`--timeout-ms` ограничивает весь Python-процесс (по умолчанию 120 000, допустимо 1 000–3 600 000 мс). Для модели учитывайте сумму времён всех запросов и внешний timeout общего runner. Превышение внешнего timeout — ошибка задания, не успешный частичный отчёт; остановку дерева подпроцессов обеспечивает инфраструктура интегратора. Кэш можно повторно использовать после проверки завершения процессов и lock.

Тесты при передаче:

```text
npm test
npm run check
```

Python-проверки запускаются командой `python -m unittest discover -s tests -v` из `modules/language`. Node-тесты включают тринадцать проверок bundle/CSV-адаптера, пилота, кандидатов и модельного протокола на синтетическом подпроцессе. Python-тесты — 120 проверок алгоритма и устойчивости. Ограничения и инструкция интегратору — в `STABILITY.md`.

## Быстрый запуск на синтетическом примере

Команды выполняются **из каталога этого модуля**. В PowerShell и обычном терминале:

```text
python examples/generate_synthetic.py ../../../locqa-private/bekzat-demo
python -m bekzat_language --input ../../../locqa-private/bekzat-demo/records.json --glossary examples/glossary.synthetic.json --cache ../../../locqa-private/bekzat-demo/cache --out ../../../locqa-private/bekzat-demo/pilot --limit 100
python -m bekzat_language --input ../../../locqa-private/bekzat-demo/records.json --glossary examples/glossary.synthetic.json --cache ../../../locqa-private/bekzat-demo/cache --out ../../../locqa-private/bekzat-demo/repeat
python -m unittest discover -s tests -v
```

Для повторного запуска выбирайте новый каталог `--out`: существующие отчёты не перезаписываются. `--cache` оставляйте прежним. Синтетические примеры придуманы для контракта; это **предложение для интеграции**, а не якобы согласованный командой пример и не выдержки из выгрузки. 100 примеров проверяют механику правил, но не являются оценкой качества на реальном датасете.

Полный запуск по подготовленным данным: та же команда **без `--limit`**. Пилот — первые 100 строк в исходном порядке; выборка не стратифицирована. Для репрезентативной проверки команда может передать собственную выборку.

## Вход и API интеграции

Вход — JSON-массив или UTF-8 JSONL. Точная схема: `schemas/record.schema.json`.

```json
{
  "key": "synthetic_gift",
  "locale": "kk",
  "source": "Отправить подарок {name}",
  "target": "{name}-ға сыйлық жіберу",
  "category": "synthetic",
  "context": "Synthetic gift action",
  "description": "Button with a runtime player name",
  "metadata": {"placeholders": {"name": {"type": "String"}}},
  "occurrence": 1,
  "source_hash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

Хэш в примере — заглушка. Интегратор передаёт SHA-256 проверяемой исходной версии и сохраняет собственную принятую семантику хэша; модуль считает поле непрозрачным и не переписывает его. Дополнительно индекс содержит `record_hash` всего входного объекта, поэтому устаревший `source_hash` не приводит к повторному использованию кэша при изменении текста.

`key`, `locale`, `source`, `target`, `occurrence`, `source_hash` обязательны. `occurrence` — целое число от 1, определённое ядром для конкретного вхождения ключа. Разные вхождения одного ключа сохраняются. Коллизия `(key, locale, occurrence)` изолирует **все** конфликтующие записи в `diagnostics.json`. Отсутствующие/пустые переводы, невалидные поля и неподдерживаемые локали также идут туда; языковой модуль не присваивает им конкурсные технические типы.

Контекст допускает строку или объект. Описание — строка; `metadata` и `@metadata` — объекты. При совпадении полей `metadata` имеет приоритет. Дополнительные поля сохраняются для модели и участвуют в кэше. JSON с повторяющимися полями или NaN отклоняется целиком; raw ARB сюда передавать нельзя.

```python
from bekzat_language import analyze

result = analyze(
    records,
    glossary,
    cache_dir="/absolute/private/path/cache",
)
findings = result["findings"]
```

Для интеграции достаточно добавить каталог модуля в `PYTHONPATH` либо запустить CLI отдельным процессом. Общий пакет/зависимости проекта меняет интегратор.

## Выход

`report.json` — массив находок, строго по `schemas/finding.schema.json`: **ровно** `key`, `issue_type`, `severity`, `source`, `target`, `evidence`, `suggestion`, `confidence`, `reviewed_by_human`. `severity`: `high | medium | low`. У каждой находки есть проверяемая цитата/признак и действие или вариант исправления. У языковой эвристики предложение может относиться к конкретному фрагменту, а не быть готовой полной заменой строки.

Другие файлы расположены рядом и не меняют общую схему находки:

| Файл | Назначение |
|---|---|
| `finding_index.json` | Связь индекса находки с входной записью, локалью, вхождением, исходным хэшем, `record_hash` и происхождением `local / corpus / model` |
| `proposals.json` | Неподтверждённые орфографические кандидаты с точным изменяемым фрагментом и хэшами |
| `diagnostics.json` | Ошибки входного контракта и провайдера; не конкурсные типы |
| `metrics.json` | Время, покрытие, попадания в кэш, запросы, токены и стоимость |
| `events.jsonl` | Журнал каждой записи: время, кэш, запросы, токены и стоимость, без текстов переводов |

`finding_index` и `input_index` отсчитываются от 0, `occurrence` — от 1. Индекс находок необходимо переносить вместе с отчётом: один `key` не идентифицирует дубль. Позиции `[start:end]` в объяснениях — индексы Unicode-символов Python, не UTF-8 байты и не UTF-16 единицы.

### Кандидаты для интерфейса проверки

`result["proposals"]` и `proposals.json` — служебный формат модуля, **не** общий журнал `reviews`. Командный адаптер кладёт файл в `<out>.details`. Кандидат содержит `finding_index`, `input_index`, `key/locale/occurrence/source_hash`, `record_hash`, `original_target_hash`, `candidate_text`, `candidate_hash` и `replacement: {start, end, original_span, text}`. Хэши текстов — SHA-256 точного UTF-8 без нормализации. Командный адаптер дополнительно сохраняет `entry_id`, `bundle_index` и `target_hash`.

Каждый кандидат меняет только один известный орфографический фрагмент; регистр, окружающий текст, числа, простые подстановки, теги и переносы сохраняются. Два кандидата одной строки независимы: их нельзя последовательно применить к уже изменённому тексту по прежним смещениям. Сложный/незакрытый ICU не получает готового кандидата. Для терминологии, кальки и динамических окончаний остаётся объяснение в находке, без автоматической полной замены.

Всегда выставлены `method: "local_spelling_span"`, `status: "pending_human_review"`, `technical_validation: "pending_core"`, `reviewed_by_human: false`. Интегратор повторно сверяет исходные хэши, проверяет кандидат ядром и показывает человеку. Только после фактического решения человека создаётся общий `reviews`. Изменение текста/контекста меняет `record_hash`; кандидат из прежней версии нельзя считать актуальным. В UI для смещений используйте последовательность Unicode code points, например `Array.from(text)`, а не прямой UTF-16 `slice`.

Коды возврата CLI: `0` — завершён выбранный режим; `2` — частичное покрытие (входные ошибки, отказ провайдера или исчерпание бюджета); `1` — ошибка настройки/чтения/записи. `status=complete` при `mode=local_only` **не означает**, что выполнен модельный проход. Для него отдельно проверяйте `model_scan_complete`.

В версии 1.1.0 повреждение SQLite-кэша даёт частичный локальный отчёт, `cache_unavailable` и `persistent_cache_available: false`. Новые вызовы модели блокируются, чтобы не оплачивать повторные запросы без работающего кэша. База сохраняется без удаления; после остановки работ интегратор может выбрать новый приватный `--cache`. Ошибка занятого кэша остаётся контролируемым отказом: сервер должен ставить задания в очередь, а не одновременно запускать несколько анализов на одном кэше.

Жёсткие пределы: входной файл 64 MiB, не более 50 000 записей, одна запись до 256 KiB, глоссарий/настройки до 1 000 000 UTF-8 байт. Большие корпуса делите на пакеты; `inconsistent_term` в таком случае видит только свой пакет. Невалидный Unicode, NaN, циклические объекты Python и слишком большая запись изолируются. Если весь вход нельзя корректно хэшировать, `records_hash` равен `null` с пояснением `records_hash_scope`; хэши валидных находок сохраняются.

## Проверки и границы

| Тип | Локальный режим | Модельный режим |
|---|---|---|
| `glossary_violation` | Явно запрещённая форма при совпадении исходного термина и области применения | Проверка термина с учётом контекста и глоссария |
| `inconsistent_term` | Явные варианты одного понятия, цитаты ключей-свидетелей | Переданные свидетели из корпуса; одиночной строки недостаточно |
| `machine_translation_suspect` | Один узкий контекстный шаблон кальки; не доказательство происхождения текста | Конкретные неестественные обороты и предложения исправлений |
| `orthography` | Небольшой список написаний; омоглифы и невидимые U+200B/U+200C/U+200D внутри известных слов | Контекстные опечатки и написания |
| `wrong_language` | Лексические признаки RU/EN/UZ во всей строке или отдельном предложении; дополнительные свидетельства из EN/UZ references | Языковая проверка с учётом имён, брендов и сленга |
| `suffix_harmony` | Известные фиксированные аффиксы после `{identifier}`, printf и простых форматированных ICU-аргументов | Контекстный риск и возможная переформулировка |

Это узкая локальная диагностика, не полноценный орфографический или морфологический анализатор. Для `wrong_language` отсутствие `ә ғ қ ң ө ұ ү һ і` само по себе ничего не доказывает. Латинизированный казахский и смешанный текст распознаются неполно. Для известного языково нейтрального текста передавайте `metadata.language_neutral: true`, для отдельных брендов/имён — `language_neutral_terms: ["DemoBrand"]`.

Если вся строка не дала `wrong_language`, проверяются фрагменты, отделённые `.!?;:` или переносом строки. Для находки нужны минимум два разных словарных признака одного языка, доля не менее половины слов фрагмента, отсутствие казахских букв и конкретная подсказка перевода. Например, вымышленное «Қош келдіңіз! Please click continue.» даёт свидетельство только для английского предложения. Отдельное «Continue» внутри смешанного текста не достаточно. Это ограниченная сегментация по пунктуации, не полноценный анализ смешанной речи или цитирования.

`suffix_harmony` сообщает риск: нужная форма зависит от значения и произношения. Предложение — передать выбор аффикса форматтеру либо перестроить фразу. Поддерживаются `{name}`, `{count, number}`, простые `date/time` со стилем, `%s`, `%1$s`, `%02d` и printf с позиционными шириной/точностью. Экранированное `%%`, очевидные ICU-литералы в апострофах, URL и атрибуты тегов исключаются. Это поиск риска в подготовленном тексте, не подтверждение валидности форматирования.

`metadata.placeholders.<name>.suffix_handled_by_runtime: true` подавляет предупреждение по явно заявленному контракту интегратора; для форматированного ICU используется имя аргумента, для printf — точный токен как ключ, например `"%1$s"`. Сложные ICU-конструкции, все варианты экранирования, цепочки аффиксов и отделённые пробелом окончания не покрываются полностью. ICU/placeholder/length-проверки принадлежат ядру.

Независимые local/model находки сохраняются раздельно, кроме полностью идентичных объектов внутри записи. Семантическую дедупликацию общего отчёта и пересечение `wrong_language` с `same_as_source` решает интегратор.

## Глоссарий

`examples/glossary.synthetic.json` показывает контракт. Верхний `status`: `draft | agreed`; статус присваивает команда. Это статус терминологии, а не флаг проверки перевода человеком. Для чернового глоссария объяснение явно указывает необходимость согласования.

Запись: уникальный `id`, `source_forms`, `allowed_forms`, `preferred`, необязательные `forbidden_forms`, `categories`, `consistent`, `variants`, `consistency_scope`. `forbidden_forms` связывает известную спорную форму с конкретной разрешённой заменой. Формы сравниваются по границам слов/фраз, без догадок о морфологии; перечисляйте окончания явно. Отсутствие разрешённой формы само по себе не даёт нарушение, чтобы не объявлять неизвестное склонение ошибкой.

`variants` связывает поверхностные формы с идентификаторами вариантов. Например, `ойыншы` и `ойыншылар` должны иметь одинаковый идентификатор. `consistent: true` включает сравнение нескольких записей. По умолчанию область сравнения — одинаковая категория; `consistency_scope: "global"` разрешает сравнивать понятие между разделами. `categories` дополнительно ограничивает применимость исходного термина. Пустой раздел не восстанавливается автоматически из имени ключа.

Командный CSV импортируется в памяти адаптером. Этот модуль не изменяет его и не объявляет предложенные термины согласованными. Перекрывающиеся варианты одного понятия сопоставляются от самого длинного к короткому: вложенная часть фразы не создаёт искусственное расхождение.

Совпадение target с `context.references.en/uz` проверяется после NFC/trim/casefold и требует лексического признака, нескольких слов и отсутствия казахских букв. Исходный RU остаётся основанием смысла; совпадение бренда с другим языком само по себе не является ошибкой. Это дополнительный сигнал для `wrong_language`, не независимая оценка качества.

## Модель, бюджет и стоимость

По умолчанию сеть не используется. Для модели предусмотрен JSON-адаптер через subprocess, `shell=False`. Интегратор подключает выбранный провайдер; в репозитории **нет** настоящего адаптера конкретного API или его ключей. Контракт проверен тестовым подпроцессом и отрицательными тестами, не платной моделью.

Скопируйте `examples/provider-config.template.json` вне репозитория, задайте команду адаптера, модель, версию и реальные тарифы. `null` в тарифах намеренно невалиден: стоимость нельзя молча считать нулевой. Команда получает на stdin JSON из `build_request`: инструкция, полная запись, глоссарий, свидетели терминов, модель, параметры и лимиты. stdout должен содержать единственный JSON:

```json
{
  "issues": [
    {"issue_type": "wrong_language", "severity": "high", "target_span": "Continue", "evidence": "В кнопке оставлен английский глагол.", "suggestion": "Жалғастыру", "confidence": 0.8}
  ],
  "usage": {"input_tokens": 300, "output_tokens": 80}
}
```

Это синтетический пример ответа. `target_span` должен быть непустой буквальной цитатой из `target`. Объяснение и предложение обязательны; неизвестные поля/типы, нечисловая уверенность и любой `reviewed_by_human` отклоняются. Только модуль строит итоговую находку с `false`. Проверка цитаты обеспечивает привязку, но не доказывает истинность языкового суждения.

Ответ stdout читается ограниченными блоками: по умолчанию максимум 2 000 000 байт, настраиваемый `max_response_bytes` — от 256 до 10 000 000. Превышение прерывает адаптер до накопления всего ответа в памяти. stderr отбрасывается без накопления. `timeout_seconds` ограничен 3600 с; по timeout прямой процесс адаптера завершается. Адаптер должен быть одним процессом и не оставлять фоновых потомков; полную изоляцию дерева процессов и лимиты CPU/RAM задаёт инфраструктура интегратора. Эта реализация не является sandbox для недоверенного исполняемого кода.

Адаптер **обязан** брать usage из ответа сервиса, не из генерации модели, учитывать reasoning/output токены и весь billable input, не делать скрытых retries. До платного запроса он должен проверить точную токенизацию и служебные накладные расходы против `input_token_limit`, задать `max_output_tokens` сервису. Если провайдер имеет дополнительные виды тарификации, адаптер/учёт требуется расширить интегратору; текущая формула учитывает только входные и выходные токены. Ключи передаются адаптеру через окружение или его штатное хранилище, не через JSON команды или файлы примеров.

```text
python -m bekzat_language --input /private/prepared.json --glossary /private/glossary.json --cache /private/cache --out /private/model-pilot --limit 100 --provider-config /private/provider.json --max-requests 100 --max-tokens 1000000 --max-cost-usd 5
```

Числа в команде — пример, не разрешённый пользователем бюджет. Для текущей передачи лимит внешних вызовов был **0**. Модельный полный проход не выполнялся.

### Отбор терминов и предварительная резервация

`glossary_scope` в конфигурации провайдера по умолчанию равен `"full"`. Необязательный `"relevant"` включает записи с точной формой RU в source/описании, известной формой KK в target или терминологическим свидетелем; учитывается категория. Исходный глоссарий не изменяется. Неизвестное склонение или синоним могут не попасть в выборку, поэтому режим требует проверки на данных команды и не включается автоматически.

Запрос содержит `glossary_selection`: режим, SHA-256 полного глоссария, число включённых/исключённых записей, размеры глоссария до и после отбора. В приватном журнале сохраняются режим, хэш и счётчики. Даже изменение исключённой записи меняет модельный ключ кэша. Уменьшение UTF-8 байтов не является измеренной экономией billable tokens.

При настроенном провайдере `metrics.budget_forecast` суммирует консервативные резервации для всех некэшированных запросов, встреченных в запуске: `uncached_records`, `uncached_reserved_tokens`, `uncached_reserved_cost_usd`, `request_bytes`, `full_glossary_bytes`, `selected_glossary_bytes`. В сумму входят и запущенные, и не поместившиеся в бюджет запросы; это оценка исходного объёма работы, не оставшийся баланс. Кэшированные ответы не требуют новой резервации.

Для оценки без внешних вызовов используйте настроенный provider-config и оставьте все бюджеты нулевыми:

```text
node modules/language/check.mjs --bundle /absolute/private/bundle.json --glossary /absolute/private/glossary.json --out /absolute/private/forecast.json --provider-config /absolute/private/provider.json --limit 100
```

Локальная диагностика и проверка кэша выполняются; новые вызовы не запускаются. Наличие некэшированных строк означает код 2 и незавершённый модельный проход. Фактические `provider_requests`, `cost_usd_total` и `input_tokens/output_tokens` остаются отдельными полями. Не представляйте forecast как выставленный счёт или гарантированную стоимость.

Лимиты запросов/токенов/денег задаются явно. Перед запросом резервируется верхняя граница: UTF-8 размер запроса + 1024 токена накладных расходов + выходной лимит. Это консервативная резервация, **не токенизатор и не гарантия для произвольного сервиса**: адаптер обязан проверить точный предел. Резервация не возвращается после дешёвого ответа, поэтому предел может закончиться раньше; остаток строк получает `budget_exhausted`. Попадания в кэш обслуживаются даже при нулевом бюджете.

Стоимость `input_tokens * input_rate / 1e6 + output_tokens * output_rate / 1e6` считается по настроенным тарифам. Фактические токены, зарезервированные токены и суммы разделены. После сетевой ошибки/таймаута без usage стоимость становится `null`, а не `$0`; новые вызовы прекращаются. Отказ с известным usage учитывает уже понесённую стоимость, но не кэшируется. Невалидный ответ никогда не считается успешной модельной проверкой. Затраты на железо, разработку и подписку не включены.

## Кэш и конфиденциальность

SQLite-кэш хранится вне любого Git checkout. Ключ включает всю запись, контекст, метаданные, хэш версии, глоссарий и версию правил. Модельный ключ дополнительно включает запрос/инструкцию, контекст свидетелей, конфигурацию и ревизию провайдера. При смене модели, адаптера или скрытого промпта интегратор обязан менять `revision`. Корпусные связи пересчитываются при каждом запуске, поэтому изменение соседней строки не оставляет устаревшее предупреждение.

Кэш и каталоги отчётов внутри Git отвергаются после разрешения абсолютного пути. Одновременные записи в один кэш блокирует `cache.lock`; после аварийного завершения удаляйте только этот lock, убедившись, что процесс с записанным PID уже не работает. Повреждённые JSON-ответы кэша проверяются и пересчитываются. SQLite хранит закрытые тексты и должен оставаться в приватном каталоге с доступом команды; шифрование модуль не обеспечивает.

JSON-файлы экспортируются через уникальный временный файл, `fsync` и атомарную замену. Неуспешная сериализация оставляет предыдущий файл целым и удаляет временный. Атомарность относится к одному файлу; для публикации всего набора сервер должен дождаться успешного завершения CLI и наличия итогового `metrics.json`, записываемого последним. Весь запуск рекомендуется выполнять отдельным фоновым заданием с обработкой кодов 0/1/2, а не в HTTP-потоке сайта.

Исходные выгрузки, производные записи, отчёты с текстами и кэш **не публиковать** и не добавлять в репозиторий. Даже файл без буквальных текстов может раскрывать производные идентификаторы; журнал тоже приватный. `.gitignore` — дополнительная защита, а не разрешение копировать данные внутрь checkout. Условия материалов требуют удаления данных в течение 14 дней после объявления победителей при отсутствии отдельного соглашения. Исходники модуль открывает только на чтение.

## Методология и известные ограничения

Модельная инструкция использует идею классификации конкретных ошибок и привязки к фрагментам из [GEMBA-MQM](https://arxiv.org/abs/2310.13988), но не воспроизводит исследовательскую метрику и не использует её название как гарантию качества. Результаты исследования не устанавливают точность этого модуля для казахского игрового текста.

Фиксированный аффикс трактуется как риск неизвестной подстановки с учётом описания гармонии в [Kazakh, Journal of the International Phonetic Association](https://www.cambridge.org/core/journals/journal-of-the-international-phonetic-association/article/kazakh/353A10BD35418B48B5A6370D9F7D8CE0). Здесь не реализовано полное правило произношения, исключений и заимствований.

`confidence` локальных правил — эвристический приоритет, модели — внутренняя уверенность генерации. Это не калиброванная вероятность, не precision и не математическая точность. В обычном metrics без человеческих меток precision/recall остаются `null`. Отдельный benchmark измеряет совпадение с объявленными синтетическими ожиданиями, не реальное качество языка. Нахождение конкретной цитаты не заменяет языковую проверку. Встроенный словарь мал, глоссарий требует согласования, а модельный адаптер и бюджет ещё должны быть предоставлены интегратором. Все исправления — предложения; отметок человеческой проверки нет.
