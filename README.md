# Qazaq Loc QA — интеграционный комплект

Основа для совместной работы пяти участников над контролем качества казахской локализации Grand Mobile. Здесь находятся общие контракты данных, синтетические примеры, независимая оценка результатов и проверки перед сдачей.

**Это ещё не готовый детектор локализации.** Ядро, языковой модуль, глоссарий с реальной проверкой носителем и интерфейс разрабатываются отдельно. `npm run demo` воспроизводит заранее подготовленные синтетические находки и проверяет обмен данными; его показатели не являются качеством работающего детектора.

## Быстрый старт

Требуется Node.js 22 или новее. Выполняйте команды из корня репозитория:

```sh
npm ci
npm test
npm run check
npm run demo
```

Для отдельной проверки совместимости ARB нужен установленный Flutter SDK:

```sh
npm run flutter-smoke -- --source fixtures/synthetic/flutter-valid/source.arb --target fixtures/synthetic/flutter-valid/target.arb --out work/flutter-synthetic
```

Flutter-проверка создаёт отдельный проект в указанном каталоге, запускает `flutter pub get` и `flutter gen-l10n`. Для каждого запуска используйте новый `--out`: существующий конечный каталог намеренно не перезаписывается. В нём сохраняются `flutter.log` и `evidence.json` со статусом и кодами завершения команд. Первый запуск может потребовать сеть для получения зависимостей. Успех на синтетической паре не заменяет прогон на итоговых файлах команды.

При подготовке комплекта локальный Flutter-прогон был заблокирован ошибкой Git `Permission denied` при доступе к SDK `C:\flutter`. Успешное выполнение `gen-l10n` локально пока не подтверждено. В CI предусмотрена отдельная проверка синтетической пары; её результат нужно смотреть в конкретном запуске GitHub Actions.

## Кто что делает

| Владелец | Область | Результат |
|---|---|---|
| Дамир | `modules/core/` | Чтение ARB, строгие проверки, CLI, безопасный экспорт |
| Бекзат | `modules/language/` | Языковые находки, предложения, журнал затрат |
| Айдана / назначенный носитель | `modules/linguistics/` | Глоссарий, реальные решения по переводам |
| Тони | `modules/report/` | HTML-отчёт и интерфейс проверки |
| Интегратор | `contracts/`, `src/`, `scripts/`, `test/`, CI | Общие форматы, оценка, сборка, проверка сдачи |

Каждый начинает на `fixtures/synthetic/`. Общие схемы, зависимости и интеграционную ветку меняет интегратор. Процесс передачи работы описан в [TEAM.md](docs/TEAM.md).

## Полезные команды

Проверить файл на соответствие схеме:

```sh
npm run validate -- --schema report --file fixtures/synthetic/report.sample.json
```

Посчитать показатели на своей размеченной выборке:

```sh
npm run evaluate -- --gold fixtures/synthetic/gold.json --report fixtures/synthetic/report.sample.json --out work/example-metrics.json
```

Этот пример проверяет арифметику оценки на известных ответах. Он не запускает детектор и не измеряет recall скрытого теста.

Сформировать воспроизводимую выборку для ручной проверки:

```sh
npm run sample-review -- --report outputs/report.json --out private/precision-sample.json --size 100 --seed review-v1
```

Объединить результаты двух детекторов:

```sh
npm run merge-reports -- --input outputs/core.json --input outputs/language.json --out outputs/report.json
```

Пути `outputs/...` и `private/...` в командах — ваши локальные результаты; в репозитории их нет.

## Данные

В Git допускаются только вымышленные примеры из `fixtures/synthetic/`. Данные организаторов, производные отчёты, исправленные переводы и журналы реальных проверок храните в игнорируемых `data/`, `private/`, `outputs/` или `submission/`. Ключи API — вне Git.

`.gitignore` не удаляет уже отслеживаемые файлы и не гарантирует отсутствие утечек. Перед публикацией проверьте состав коммита. Финальный пакет с данными передаётся организаторам предусмотренным ими способом.
