# Синтетические примеры разработки

Все строки и ключи в этой папке придуманы для проекта. Здесь нет выгрузок заказчика, производных выборок из них или ответов на скрытые ошибки организаторов.

**Это открытый набор для разработки и проверки интерфейсов, не независимый финальный benchmark.** Казахские формулировки, глоссарий и лингвистические метки предварительные: носитель их не проверял. Ни один пример не содержит настоящего человеческого одобрения.

## Основная пара

- `source.arb` — вымышленный исходник RU.
- `target.arb` — соответствующий KK с намеренно внесёнными дефектами.
- `glossary.csv` — условные правила этого набора; они не задают терминологию игры.
- `gold.json` — 11 ожидаемых пар `key + issue_type`.
- `report.sample.json` — заранее написанный пример отчёта с точными текстами из пары ARB. Это **не результат запуска детектора**.
- `negatives.json` — семь примеров, которые не должны становиться находками в контексте этого набора.

У отсутствующей целевой строки в отчёте `target` равен пустой строке. У всех находок `reviewed_by_human: false`. Числа `confidence` демонстрационные, не калиброванные вероятности.

| Ключ | Ожидаемый тип | Условие примера |
|---|---|---|
| demoMissingExitLabel | untranslated | Ключ отсутствует в KK |
| demoUntranslatedAction | same_as_source | Русская фраза повторена целиком |
| demoParcelNotice | placeholder_mismatch | recipient заменён на recipent |
| demoTokenBalance | plural_mismatch | В KK отсутствует other |
| demoGuildHall | glossary_violation | Нарушен условный глоссарий |
| demoShortTab | length_overflow | Короткая вкладка заменена длинной инструкцией |
| demoNaturalNotice | machine_translation_suspect | Предварительный пример неестественного порядка слов |
| demoTicketCounter | inconsistent_term | Термин отличается от demoTicketHelp, который выбран опорным |
| demoInviteName | suffix_harmony | После неизвестного имени стоит фиксированное -ға |
| demoQuestionLabel | orthography | Предварительный пример у вместо ұ |
| demoAirshipAudio | wrong_language | Английская фраза в KK |

Для `length_overflow` это эвристическая метка: реальных размеров и шрифта интерфейса нет. Лингвистические метки не исключают других интерпретаций без контекста и проверки носителем.

Негативные примеры проверяют допустимые совпадения бренда/числа/заимствования, сохранение специального символа шрифта, корректных плейсхолдеров, printf-токенов и тегов. `cleanLocalePlural` специально имеет разные наборы категорий в RU и KK: наличие русских `few/many` не означает, что их надо копировать в казахский.

## Краевые случаи

- `edge-cases/duplicate-normal-conflicting.arb` содержит два разных значения одного обычного ключа. Не пересохранять этот файл через `JSON.parse → JSON.stringify`: потеряется первое вхождение. Это структурная диагностика вне конкурсных 11 типов.
- `edge-cases/repeated-comments.arb` содержит три `@@comment`. Нужно сохранить порядок и принадлежность строк разделам.
- `edge-cases/icu-nested-escaped-*.arb` содержит вложенные `select/plural`, литеральные фигурные скобки и апостроф. Эти файлы совпадают с парой ниже и предназначены для тестов парсера.

## Пара для Flutter smoke-test

`flutter-valid/source.arb` и `flutter-valid/target.arb` предназначены для реального запуска `flutter gen-l10n` в минимальном проекте. В каждой ветви ICU есть `other`, у переменных есть метаданные. Для вывода числа внутри plural используется явный `{count}`, как в примерах Flutter, а не символ `#`. Используйте `use-escaping: true` в `l10n.yaml`. Название папки описывает назначение пары, а успешность компиляции должна подтверждаться запуском Flutter.

Основной `target.arb` намеренно сломан и не должен использоваться как положительный smoke-test. Структурная компиляция не означает, что перевод одобрен носителем.

## Проверка

Из корня репозитория:

```sh
node --test test/fixtures.test.mjs
```

Тесты проверяют согласованность разметки и отчёта с входными файлами, покрытие типов и отсутствие ложных отметок проверки. Они не заменяют ICU-парсер, Flutter или оценку перевода.

Сравнение `report.sample.json` с `gold.json` проверяет только работу вычислителя метрик. Полученный результат нельзя представлять как точность детектора.
