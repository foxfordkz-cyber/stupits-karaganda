# Явное разрешение конфликтующих ключей

Команда `npm run audit-inputs -- --source data/intl_ru.arb --target data/intl_kk.arb --out private/input-audit.json` сохраняет все варианты конфликтующих ключей. Очередь не выбирает вариант автоматически и не создаёт одобрений человека.

Человек выбирает существующее вхождение. Его решение записывается отдельно в формате contracts/duplicate-resolutions.schema.json. source_sha256 и original_target_sha256 — SHA256 точного UTF-8 содержимого файлов; occurrence — номер вхождения ключа, начиная с 1; chosen_hash — SHA256 выбранного текста. reviewer, reviewed_at и reviewed_by_human=true заполняются только после реального решения человека.

Передайте этот файл как `--resolutions private/duplicate-resolutions.json` в release-check и package-submission. Каждому конфликтующему ключу требуется одно актуальное решение; неизвестные ключи, неверные хэши и повторные решения отклоняются.

Решение разрешает убрать неоднозначность, но не заменяет проверку нового перевода. Для сравнения изменений исходным значением остаётся последнее вхождение, которое использует обычный JSON-разбор. Если итог отличается от него, нужны обычное решение reviews и отметка @key.x-locqa. Это относится и к выбору более раннего варианта. Итог должен совпадать с выбранным вариантом либо с явно одобренной последующей коррекцией.

Конфликтующие дубли в source требуют отдельного решения по исходному контракту, поэтому gate продолжает блокировать их. Не переименовывайте игровые ключи и не подменяйте исходные файлы ради успешного прогона.
