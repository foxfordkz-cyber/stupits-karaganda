# Результаты проверки человеком

Эти команды считают только введённые человеком решения. Они не выполняют проверку за носителя, не выставляют одобрение перевода и не измеряют recall по скрытым ошибкам.

Все реальные входы, анкеты, ключи и результаты храните в игнорируемых `private/`, `data/`, `outputs/`. До проверки зафиксируйте входной отчёт, размер выборки и seed. Не перебирайте seed ради удобных примеров.

## Проверка precision

Создать выборку:

```sh
npm run sample-review -- --report outputs/report.json --out private/precision-sample.json --size 100 --seed final-v1
```

У каждой строки человек заполняет `reviewed: true`, `correct: true` или `false`, своё имя в `reviewer` и время в `reviewed_at` в формате ISO с часовым поясом, например `2026-10-30T18:00:00+06:00`. Проверяется и наличие ошибки, и правильность её типа. Замечания можно оставить в `notes`. Если старый шаблон не содержит `reviewed_at`, добавьте это поле. У непроверенных строк `reviewed`, `correct`, `reviewer` и `reviewed_at` остаются `null`; дата может отсутствовать в старом незаполненном шаблоне.

```sh
node scripts/score-review.mjs --sample private/precision-sample.json --report outputs/report.json --out private/precision-results.json
```

Команда заново восстанавливает выборку по исходному отчёту, seed и размеру. Она отклоняет удалённые/повторённые строки, изменённые тексты находок, подменённые идентификаторы и неполные ответы. Исходный отчёт не меняется. Новый шаблон также содержит report_sha256 всего отчёта: изменение даже не выбранной строки блокирует оценку. Старые шаблоны без этого хэша читаются, но считаются привязанными только к выбранным находкам; для них report_precision_estimate остаётся null.

Результат содержит подтверждённые, отклонённые и непроверенные находки. `precision_on_reviewed` относится только к просмотренной части. `report_precision_estimate` появляется только после проверки всей выбранной выборки; частичное заполнение может быть смещено в сторону лёгких случаев. Wilson 95% — биномиальное приближение без поправки на конечную совокупность. Если просмотрен весь отчёт, неопределённости из-за выборки уже нет. При нулевом знаменателе оценка равна `null`, а не 100%.

## Слепое сравнение исправлений

Предпочтительно дать сравнение другому носителю, который не готовил исправления. Подготовить анкету и отдельный закрытый ключ:

```sh
node scripts/blind-review.mjs --source data/intl_ru.arb --original-target data/intl_kk.arb --fixed submission/intl_kk_fixed.arb --out private/blind-sheet.json --key-out private/blind-key.json --size 150 --seed frozen-blind-v1
```

Скрипт выбирает только изменённые строки, перемешивает их и положение вариантов A/B. Неизменённые строки исключены. Неоднозначные дубли блокируют подготовку без принятого решения. Если есть конфликтующие дубли, передайте обеим blind-командам `--resolutions private/duplicate-resolutions.json`: проверяются подписи выбора и хэши исходных файлов, каждый конфликт должен иметь решение. Сравниваемым исходником остаётся последнее вхождение ключа, то есть исходное значение runtime; решение по дублю не подменяет baseline. Хэш решения включается в закрытый ключ. Удаление исходных ключей и изменения ключей без оригинального текста также блокируются. Отсутствующий исходный перевод представлен `null`, а существующий пустой перевод — `""`. Это разные состояния.

**Проверяющему передаётся только blind-sheet.json.** Seed, закрытый ключ и информация о том, какая сторона исправлена, ему не передаются. В анкете есть исходный текст, варианты A/B и поля ответа без отметок авторства. Скрипт не заменяет уже существующую анкету или ключ, чтобы не потерять ответы.

В каждой просмотренной строке заполнить:
- `preference`: `A`, `B`, `tie` или `cannot_assess`;
- `reviewer`: имя проверившего;
- `reviewed_at`: время ISO с часовым поясом;
- `notes`: пояснение при необходимости.

Непросмотренная строка остаётся с `preference: null` и пустыми данными проверяющего. После фиксации ответов интегратор раскрывает ключ и считает результат:

```sh
node scripts/score-blind.mjs --source data/intl_ru.arb --original-target data/intl_kk.arb --fixed submission/intl_kk_fixed.arb --sheet private/blind-sheet.json --key private/blind-key.json --out private/blind-results.json
```

При расчёте проверяются хэши всех трёх файлов, закрытый ключ и неизменность текстов/состава анкеты. Изменение файла, даже вне выбранных строк, требует подготовки новой анкеты. Скрипт отдельно считает улучшения, ухудшения, равенства, невозможность оценки и непроверенные строки. `correction_win_rate` — доля улучшений среди сравнимых ответов (равенства входят в знаменатель), `net_preference` — (улучшения − ухудшения) / сравнимые ответы. Это описание данной оценки, не формула судейского балла.

Инструмент не может доказать личность, носительский уровень или независимость человека. Если оценивал тот же человек, который исправлял строки, явно укажите это в методологии. Хэш защищает от случайной подмены версий, но не делает поддельную человеческую подпись настоящей.
