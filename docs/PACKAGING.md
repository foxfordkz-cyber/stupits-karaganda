# Проверяемый пакет сдачи

Упаковщик работает локально и ничего не публикует. Он нужен после подключения модулей команды и реальной проверки переводов человеком.

## Создание

```sh
node scripts/package-submission.mjs --source data/intl_ru.arb --original-target data/intl_kk.arb --fixed submission/intl_kk_fixed.arb --report submission/report.json --reviews private/reviews.json --glossary submission/glossary.csv --html submission/report.html --methodology submission/methodology.md --flutter-evidence work/flutter-final/evidence.json --flutter-log work/flutter-final/flutter.log --out submission/ready-v1
```

Все входы обязательны. Выходной каталог должен быть новым. Если запись была прервана, повторите команду с новым каталогом: упаковщик не перезаписывает существующие файлы и не удаляет частичный результат.

Проверки перед записью:

1. Заново выполняется `checkRelease` на переданных ARB, находках и решениях человека. Готовый файл со словом «passed» не заменяет эту проверку.
2. Проверяется CSV-глоссарий, наличие самостоятельного HTML и непустой методологии.
3. Flutter evidence должен содержать успешные `flutter --version`, `flutter pub get`, `flutter gen-l10n`, коды завершения 0 и корректные даты. Допускаются явно записанные варианты с --no-version-check и pub get --offline; журнал обязан содержать именно выполненные команды.
4. Хэши source и fixed обязаны совпасть с точными файлами, проверенными Flutter. Изменение даже переноса строки после прогона требует нового прогона.
5. Проверяется наличие заголовков всех команд в журнале. Обязательный `log_sha256` связывает evidence с точным журналом. `generated_sha256` должен содержать SHA-256 сгенерированного Dart-файла; сам Dart-файл в этот пакет не входит.

Конфликтующие дубли исходных ARB блокируют выпуск, пока команда не разрешит их явно. Не заменяйте baseline молча ради прохождения проверки. Необязательный `--resolutions` передаёт журнал решений общему release gate и включает его в пакет; его формат определяется общим контрактом интегратора.

## Что создаётся

Снимки входных файлов копируются без изменения байтов. Внутри пакета находятся оригиналы, исправленный `intl_<locale>_fixed.arb`, отчёт, журнал решений, глоссарий, методология, evidence и log Flutter, пересчитанная проверка `checks/preflight.json`.

`manifest.json` записывается последним. Он содержит обязательные роли файлов, относительные имена, размеры и SHA-256. Входы сначала читаются и проверяются как единый снимок, поэтому упаковка не подменяет проверенные данные новой версией файла.

Пакет содержит данные кейса. Передайте его организаторам установленным способом; не размещайте его в публичном GitHub или публичных артефактах CI.

## Проверка перед передачей

```sh
node scripts/package-submission.mjs --verify submission/ready-v1
```

Проверка повторно считает контрольные суммы, требует полный набор файлов, отклоняет незаявленные файлы, небезопасные пути и символические ссылки, затем повторяет semantic preflight и привязку evidence к ARB. Удалённый, изменённый или подменённый файл приводит к ненулевому коду завершения.

## Что это доказывает

Успех подтверждает целостность пакета, согласованность одобрений и связь представленного Flutter evidence с точными входами. Хэши не удостоверяют личность носителя и не доказывают реальность произвольного вручную написанного журнала. Доверие к запуску подтверждается отдельным проверяемым CI/run или воспроизведением команды.

Упаковщик не оценивает естественность казахского, не вычисляет неизвестный recall организаторов и не заменяет проверку итоговых переводов носителем.
